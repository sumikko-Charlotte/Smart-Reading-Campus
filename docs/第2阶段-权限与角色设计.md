# 第 2 阶段 · 权限与角色设计（已落地版）

> 对应 10 月 18 日组会第 1 项议题。本文档是**实现对照文档**：每个设计点都标注了代码位置，
> 验收时可直接按「怎么验证」一列复现。

## 1. 角色模型

```
visitor（访客）        只读浏览 + AI 推荐走降级 Mock
student（学生）        报名 / 漂流 / 证书 / AI 伴读；按需授予「申办活动」
admin（普通管理员）    申办 / 审批定级 / 漂流运营 / 发总结
super_admin（系统管理员）全部权限 + 用户管理 + 权限分配
```

- 旧 `librarian` 角色已并入 `admin`，数据库迁移在 `app/db/base.py init_db()` 自动完成。
- 代码位置：`app/core/enums.py UserRole`。

## 2. 权限模型：角色给默认值，权限逐项可配

**有效权限 = 角色默认权限 − 收回 + 额外授予**

- 15 个权限点，编码 `资源:动作`，目录见 `app/core/permissions.py PERMISSION_CATALOG`。
- 用户表新增 `granted_permissions` / `revoked_permissions` 两个 JSON 字段。
- 接口校验一律走权限点：`Depends(require_permissions(Permission.XXX))`，
  业务代码不再写 `if role == 'admin'`。
- token 里的角色只做兜底，**每次请求都读数据库算有效权限**，改权限即时生效（不用重新登录）。

### 防越权硬约束（写在代码里，不靠自觉）

1. 不能修改**自己**的角色/权限（防自提权、防把自己锁死）
2. 不能通过接口创建或提升「系统管理员」（防越权链）
3. `system:permission` 不可授予任何账号（仅角色天然携带）
4. 审批人**不能审批自己申办的活动**（系统管理员除外）
5. 每次变更写 `permission_logs` 审计表：操作人、对象、动作、前后值、备注

代码位置：`app/api/v1/permission.py`。

## 3. 活动审批流与定级

```
draft ──提交──▶ pending_review ──通过──▶ published ──▶ signup_closed ──▶ ongoing ──▶ finished
  │                  │                                        │
  └──取消────────────┴──驳回──▶ rejected ──修改后重新提交──┘   └──取消（旁支）
```

- 审批通过**必须定级**：`school`（校级）/ `college`（院级），写入 `activities.level`。
- 驳回必须填写原因，申办人修改后可再次提交。
- 学生会成员（被授予 `activity:create` 的学生）与管理员走同一条审批链。
- 代码位置：`app/api/v1/activity.py` 的 `/submit`、`/review`；状态机在 `app/core/enums.py ACTIVITY_STATUS_TRANSITIONS`。

## 4. 电子证书（PDF + 公章）

- 学生完成签到与签退后由系统自动发放，一人一活动一张（数据库唯一约束兜底）。
- PDF 由**服务端**渲染（`app/services/certificate_service.py`，reportlab + 本机中文字体）：
  - 级别徽标（校级/院级）、持有人、学号、活动名
  - **圆形公章为代码绘制**（单位名环形排布 + 五角星），校级盖章单位默认「北京邮电大学图书馆」
  - 证书编号 `ZYYC-年份-S/C-8位验真码`
- 公开验真接口：`GET /certificates/verify/{verify_code}`（无需登录，返回脱敏姓名）。
- 下载接口仅本人可访问；证书列表与 PDF 下载都只对学生开放。
- 接口：`/certificates/mine`、`/certificates`、`/certificates/{id}/pdf`、`/certificates/verify/{code}`、`/activities/{id}/certificates`、`/certificates/{id}/revoke`。

## 5. 活动总结与站内消息

### 5.1 总结发布

- 活动开始后即可撰写总结（草稿），**发布权在人**；发布时选择推送角色（学生/访客/管理员）。
- 发布后**定向推给报名过该活动的学生**（见 5.2），未报名的人不会被别人的活动刷屏；
  没有报名记录的展示类活动退化为按所选角色广播，避免无人收到；访客没有报名关系，始终按角色广播。
- 已发布总结同时进入全站活动流，访客可见。

### 5.2 消息投递：定向 + 广播

`notifications` 一张表支持两种投递方式，靠 `user_id` 区分：

| 类型 | `user_id` | 可见人 | 用于 |
|---|---|---|---|
| 定向 | 有值 | 仅该用户 | 审批结果、权限变动、证书颁发、活动取消 |
| 广播 | 空 | `target_roles` 包含其角色的人 | 全站公告、访客可看的活动总结 |

已读状态存在 `notification_reads(notification_id, user_id)`，一个用户对一条消息最多一条记录；
广播消息不会为每个用户复制正文，1000 人看同一条也只有一条 `notifications`。

### 5.3 事件与消息对照

| 业务动作 | 收件人 | 消息 |
|---|---|---|
| 提交权限申请 | 所有有效权限含 `system:permission` 的人 | 待审批权限申请（含权限中文名与理由） |
| 权限审批通过 / 驳回 | 申请人 | 已通过（列出实际开通的权限）/ 已驳回（附审批意见） |
| 管理员直接调权限 / 改角色 | 被调整人 | 新开通 / 已收回的权限，或角色变化 |
| 活动提交审批 | 所有有效权限含 `activity:review` 的人 | 待审批活动 |
| 活动审批通过 / 驳回 | 申办人 | 已发布 + 定级 / 被驳回 + 意见 |
| 活动状态变为报名截止/开始/结束/取消 | 该活动报名者 | 状态更新 / 活动取消 |
| 活动总结发布 | 该活动报名者（访客广播） | 你参加的活动发布了回顾 |
| 证书颁发 | 获证学生 | 你获得了活动证书（含证书编号） |

**待办自动消账**：审批人处理完一条申请/活动后，对应的「待审批」消息由后端自动标记已读，
红点立即减少，避免「处理完了红点还挂着」。

### 5.4 未读数与红点

- `GET /notifications/unread-count` 返回当前用户未读数，是顶栏红点的唯一数据源；
  可见性与列表、标记已读共用 `notification_service.visible_notifications`，不会出现「红点 3 条点进去 1 条」。
- 前端刷新策略：每 10 秒轮询 + 切页刷新 + 审批等操作后立即拉取 + 标签页切回前台补一次。
- 接口：`POST /activities/{id}/summary`、`POST /summaries/{id}/publish`、`GET /summaries`、
  `GET /notifications`、`GET /notifications/unread-count`、`POST /notifications/{id}/read`、`POST /notifications/read-all`。

## 6. 访客（visitor）边界

| 能 | 不能 |
|---|---|
| 浏览已发布/进行中/已结束活动 | 报名、申办（可在个人中心申请，审批通过后获得） |
| 查看漂流池与流转状态 | 上架、申领（同上，按申请结果开放） |
| AI 推荐（**强制本地 Mock，不消耗模型额度**） | AI 伴读对话 |
| 看活动流、收推送 | 看任何用户个人信息 |
| 在个人中心提交权限申请，由系统管理员审批 | 修改公共账号的资料与密码 |

访客申请走的是同一套 `permission-requests` 接口：提交后系统管理员在「用户与权限 → 权限申请」里能看到
`role=visitor` 的申请并审批，通过即写入 `granted_permissions`，无需换账号。

访客支持两种形态：匿名请求（`get_optional_user` 返回访客上下文）或演示账号 `guest` 登录。
Mock 推荐理由只描述书目本身，不出现「和你相似的同学」等可逆指向，与脱敏数据使用边界一致。

## 7. 前端权限控制（web-pc）

- 路由 `meta.permission` + 全局守卫（`src/router/index.js`）
- 菜单按权限过滤（`BasicLayout.vue`），访客显示「访客只读模式」横幅
- 按钮级：报名/上架/审批/总结/证书按钮按 `store.can(PERM.XXX)` 显隐
- 新页面：
  - `/login` 登录（顶部三入口：登录 / 注册 / 访客）
  - `/register` 注册（先选学生或管理员，注册成功自动登录）
  - `/profile` 个人中心（资料、我的权限、我的申请、账号安全）
  - `/activities/review` 活动审批（通过时选校级/院级）
  - `/certificates` 我的证书（仅学生端，下载 PDF + 验真）
  - `/system/users` 用户与权限（角色 + 逐项勾选 + 权限申请 + 变更日志）
  - `/activities` 活动信息流（活动推送 + 活动总结）、`/activities/:id/summary` 总结编辑、`/notifications` 消息

## 8. 账号入口与权限申请

### 8.1 三种进入方式

| 入口 | 接口 | 说明 |
|---|---|---|
| 登录 | `POST /auth/login` | 注册用户校验 PBKDF2 哈希；演示账号无哈希时回退到 `123456` |
| 注册 | `POST /auth/register` | 只允许 `student` / `admin`；`super_admin` 不可注册、`visitor` 免注册；返回 token，注册即登录 |
| 访客 | `POST /auth/guest` | 复用 `guest` 账号签发 token，拿到只读身份 |

密码存储：`users.password_hash`，格式 `pbkdf2_sha256$120000$盐$摘要`，每用户随机盐；改密后原演示密码失效。

### 8.2 权限申请

```
学生 / 管理员                     系统管理员
    │ 勾选权限 + 理由                │
    ├─ POST /permission-requests ──> │ pending
    │                               ├─ GET /permission-requests（仅 system:permission）
    │                               ├─ POST /{id}/review {approve:true}
    │ <──────── 权限写入 granted_permissions + PermissionLog
```

- 表：`permission_requests`（申请人快照、权限列表、理由、状态、审批人、审批意见）
- 状态：`pending → approved / rejected / cancelled`
- 约束：不能申请 `system:permission`；已拥有的权限不能重复申请；同一权限审批中不能重复提交；不能审批自己的申请；已处理的申请不能重复审批
- 审批通过后**立即生效**（每次请求查库重算），申请人无需重新登录
- 只有 `system:permission` 持有者能看全量申请；学生与普通管理员只能看 `GET /permission-requests/mine`
