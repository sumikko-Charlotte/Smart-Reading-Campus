> 适用范围：第 1 轮开发周期（2026-10-06 ~ 2026-10-18）
> 目标：**统一字段口径，按变更记录维护，避免双端（PC 端 Vue / 微信小程序）联调时数据不一致**
> 维护人：项目组　｜ 需要变更时：在本文件登记「变更记录」后同步后端 Schema 与前端字段常量

## 一、全局约定（必须先看这一节）

### 1.1 命名规则

| 项目       | 约定                 | 说明                                              |
| -------- | ------------------ | ----------------------------------------------- |
| JSON 字段名 | `snake_case`       | 前后端保持一致，不做自动驼峰转换，减少联调歧义                         |
| 对象名      | 大驼峰                | `User` / `Activity` / `Book` / `AIConversation` |
| 枚举值      | 小写 `snake_case` 英文 | 如 `signup_closed`，中文只用于展示映射                     |
| URL 路径   | 复数、小写、中划线          | `/api/v1/activities`、`/api/v1/ai/conversations` |

### 1.2 主键规则（重要）

**所有主键统一为字符串（string），格式 `前缀 + 12 位十六进制`**，例如 `usr_9f2a1c77b0d4`。

- 前缀：`usr_` 用户、`act_` 活动、`bok_` 图书、`cnv_` 会话、`drf_` 漂流记录、`sgn_` 报名记录、`rpt_` 活动报道、`msg_` 消息
- **不使用自增 int64 作为对外主键**：JS `Number` 精度有限，用字符串可避免小程序/PC 端 ID 被截断

### 1.3 时间与时区

- 统一使用 **ISO 8601 带时区偏移字符串**，时区 `+08:00`，例：`"2026-10-18T12:00:00+08:00"`
- 字段名统一 `_at` 结尾表示「时间点」，`_date` 结尾表示「日期」
- 后端存储用 UTC，序列化时统一转换为 `+08:00`

### 1.4 通用基础字段（BaseModel，所有业务对象统一继承）

`User`、`Activity`、`Book`、`AIConversation` 以及后续新增的 `ActivitySignup`、`ActivityReport`、`DriftRecord` 等业务对象，统一继承 `BaseModel`。除各对象自身业务字段外，默认都包含以下通用字段；后续对象表格中即使只简写 `created_at / updated_at`，也视为同时包含 `is_deleted`。

| 字段           | 类型               | 必填 | 说明                                 |
| ------------ | ---------------- | -- | ---------------------------------- |
| `created_at` | string(datetime) | 是  | 创建时间，服务端生成，客户端只读                   |
| `updated_at` | string(datetime) | 是  | 最后更新时间，服务端生成，客户端只读                 |
| `is_deleted` | boolean          | 是  | 软删除标记，默认 `false`；列表接口默认只返回 `false` |

### 1.5 空值规范

- 普通可选文本无值用 `""`；必填文本不得为空。可选日期、时间点及不存在的关联 ID 使用 `null`，禁止用空字符串代替日期或时间。
- 数值：计数类统一用 `0` 而非 `null`
- 数组：无值用 `[]`，禁止 `null`
- 布尔：禁止用 `0/1` 代替 `true/false`

### 1.6 统一响应体

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "trace_id": "d8f1c2a4b6e9"
}
```

| code | 含义                  |
| ---- | ------------------- |
| 0    | 成功                  |
| 1001 | 参数校验失败              |
| 1002 | 未登录 / token 失效      |
| 1003 | 无权限（RBAC 拦截）        |
| 1004 | 资源不存在               |
| 1005 | 业务状态非法（如未发布的活动不能签到） |
| 5000 | 服务器内部错误             |

### 1.7 统一分页

请求参数：`page`（从 1 开始，默认 1）、`page_size`（默认 20，最大 100）、`keyword`（模糊搜索）、`order_by`、`order`（`asc`/`desc`）

响应 `data`：

```json
{
  "list": [],
  "page": 1,
  "page_size": 20,
  "total": 128
}
```

## 二、User（用户）

**用途**：PC 端管理后台与小程序端的统一账号主体，承载 RBAC 权限。

| 字段                          | 类型               | 必填 | 说明                                |
| --------------------------- | ---------------- | -- | --------------------------------- |
| `user_id`                   | string           | 是  | 主键，`usr_` 前缀                      |
| `student_no`                | string           | 是  | 学号/工号，**登录账号，全局唯一**               |
| `name`                      | string           | 是  | 姓名                                |
| `role`                      | enum             | 是  | 见 2.1 角色枚举                        |
| `college`                   | string           | 否  | 学院，如「未来学院」                        |
| `major`                     | string           | 否  | 专业，如「电子信息（元班）」                    |
| `class_no`                  | string           | 否  | 班级，如「2025217802」                  |
| `grade`                     | string           | 否  | 年级，如「2025」                        |
| `phone`                     | string           | 否  | 手机号（加密存储，接口按权限脱敏）                 |
| `email`                     | string           | 否  | 邮箱                                |
| `avatar_url`                | string           | 否  | 头像地址，默认 `""`                      |
| `status`                    | enum             | 是  | `active` / `disabled`，默认 `active` |
| `last_login_at`             | string(datetime) | 否  | 最后登录时间                            |
| `created_at` / `updated_at` | string(datetime) | 是  | 通用字段                              |

### 2.1 角色枚举 `role`

| 值           | 含义         | 权限范围                   |
| ----------- | ---------- | ---------------------- |
| `student`   | 学生（小程序端主体） | 浏览活动、报名签到、AI 伴读、图书漂流   |
| `librarian` | 图书馆老师      | 管理端全部业务数据（活动/图书/AI 素材） |
| `admin`     | 系统管理员      | 含用户管理、权限配置、数据导出        |

> RBAC 落地：后端接口注解 `@require_roles("librarian", "admin")`，前端路由 `meta.roles` 过滤菜单。

### 2.2 隐私约定

- `phone`、`email` 在**非本人、非管理员**请求下返回脱敏值：`177****3115`、`21****@qq.com`
- 加密存储字段（后续接 AES-GCM）：`phone`、`email`

## 三、Activity（阅读推广活动）

**用途**：活动全生命周期闭环管理（发起 → 招募 → 签到 → 报道 → 公示 → 电子证书 → 成果展示）。

| 字段                          | 类型               | 必填 | 说明                     |
| --------------------------- | ---------------- | -- | ---------------------- |
| `activity_id`               | string           | 是  | 主键，`act_` 前缀           |
| `title`                     | string           | 是  | 活动标题                   |
| `subtitle`                  | string           | 否  | 副标题/一句话卖点              |

| `cover_url`                 | string           | 否  | 封面图，默认 `""`            |
| `summary`                   | string           | 否  | 简介（列表页展示，建议 ≤ 120 字）   |
| `content`                   | string           | 否  | 详情富文本（PC 端管理，小程序端渲染）   |
| `location`                  | string           | 否  | 活动地点                   |
| `organizer_id`              | string           | 是  | 主办方/创建人 `user_id`      |
| `organizer_name`            | string           | 是  | 冗余字段，避免列表页 N+1 查询      |
| `signup_start_at`           | string(datetime) | 否  | 报名开始时间                 |
| `signup_end_at`             | string(datetime) | 否  | 报名截止时间                 |
| `start_at`                  | string(datetime) | 是  | 活动开始时间                 |

| `capacity`                  | int              | 是  | 名额上限，`0` 表示不限          |
| `signup_count`              | int              | 是  | 已报名人数（服务端维护，只读）        |
| `checkin_count`             | int              | 是  | 已签到人数（服务端维护，只读）        |
| `need_certificate`          | boolean          | 是  | 是否自动颁发电子证书，默认 `false`  |
| `certificate_template_id`   | string           | 否  | 证书模板 ID                |
| `ai_copy`                   | string           | 否  | AI 生成的宣传推文（管理端一键生成后暂存） |
| `status`                    | enum             | 是  | 见 3.2 状态机              |
| `published_at`              | string(datetime) | 否  | 发布时间                   |
| `created_at` / `updated_at` | string(datetime) | 是  | 通用字段                   |

### 3.1 分类枚举 `category`

| 值                   | 含义      |
| ------------------- | ------- |
| `reading_share`     | 读书分享会   |
| `lecture`           | 讲座/沙龙   |
| `exhibition`        | 书展/展览   |
| `reading_challenge` | 阅读打卡/挑战 |
| `book_drift`        | 图书漂流活动  |
| `other`             | 其他      |

### 3.2 状态机 `status`（管理端与小程序端必须共用）

```
draft(草稿) ──publish──▶ published(已发布) ──close_signup──▶ signup_closed(报名截止)
                                   │                                  │
                                   └────────cancel───▶ cancelled      └──start──▶ ongoing(进行中)
                                                                                     │
                                                                                  finish
                                                                                     ▼
                                                                            finished(已结束)
```

| 值               | 展示文案 | 是否可编辑 | 是否可报名 |
| --------------- | ---- | ----- | ----- |
| `draft`         | 草稿   | 是     | 否     |
| `published`     | 已发布  | 是     | 按 7.2 判断 |
| `signup_closed` | 报名截止 | 是     | 否     |
| `ongoing`       | 进行中  | 是     | 否     |
| `finished`      | 已结束  | 否     | 否     |
| `cancelled`     | 已取消  | 否     | 否     |

> **非法流转必须由后端拦截并返回 `code=1005`**，前端只做按钮可用性提示，不做唯一判断。

### 3.3 派生对象（本轮定义字段，实现周期另行确认）

> **命名定版：**活动报名/参与关系统一使用 `ActivitySignup`，后续文档、FastAPI Schema、数据库表及前端类型中不再使用 `ActivityParticipant`，避免同一业务对象出现两套命名。

| 对象               | 关键字段                                                                                                     | 说明                                                           |
| ---------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `ActivitySignup` | `signup_id` / `activity_id` / `user_id` / `status` / `signed_up_at` / `checked_in_at` / `certificate_no` | 报名与签到记录，状态：`pending` / `approved` / `rejected` / `cancelled` |
| `ActivityReport` | `report_id` / `activity_id` / `title` / `content` / `images[]` / `published_at`                          | 活动报道与成果展示                                                    |

### 4.1 图书漂流扩展字段（`source = drift` 或 `both` 时适用）

| 字段                  | 类型     | 说明                                                                                |
| ------------------- | ------ | --------------------------------------------------------------------------------- |
| `drift_id`          | string | 漂流记录 ID，`drf_` 前缀                                                                 |
| `drift_status`      | enum   | `idle`(待领取) / `reserved`(已预定) / `in_transit`(流转中) / `claimed`(已领用) / `closed`(下架) |
| `current_holder_id` | string或null | 当前持有者 `user_id`；无持有者时为 `null` |
| `drift_location`    | string | 线下交接地点，如「图书馆一层大厅」                                                                 |
| `drift_count`       | int    | 累计流转次数                                                                            |

> **第 1 轮实现约定：**上述漂流扩展字段可暂时作为 `Book` 的开发占位字段，用于页面原型、接口 Mock 与最小链路联调，不要求本轮完成独立漂流表。
>
> **正式实现拆分约定（具体周期另行确认）：**将漂流业务独立为 `DriftRecord` 对象及 `drift_records` 表，`Book` 仅保留图书主数据；漂流状态、持有者、交接地点、流转次数等业务字段迁移至 `DriftRecord`。字段口径以上表为准，拆分时不得由双端自行改名。
>
> **本轮实际实现：**已直接采用拆分后的形态——漂流字段全部落在 `DriftRecord`（`drift_records` 表），`Book` 不保留漂流字段；接口以 `POST /drift/books` 上架、`POST /drift/records/{drift_id}/claim` 申领，接口清单以启动后的 `/docs`（OpenAPI）为准。

**用途**：承接 AI 阅读助手（多轮伴读）、AI 书目解读、AI 推荐解释、宣传文案生成四类场景，统一存消息流。

| `message_count`             | int              | 是  | 消息条数                                    |
| `prompt_version`            | string           | 是  | 提示词版本号，如 `v1.0-book-analysis`，便于效果回溯    |
| `status`                    | enum             | 是  | `active` / `archived`，默认 `active`       |

### 5.1 场景枚举 `scene`

| 值               | 含义        | 对应端           |
| --------------- | --------- | ------------- |

| `qa`            | 多轮伴读问答    | 小程序端为主，PC 端可用 |

### 5.2 消息对象 Message

| 字段           | 类型               | 必填 | 说明                              |
| ------------ | ---------------- | -- | ------------------------------- |
| `message_id` | string           | 是  | 消息 ID，`msg_` 前缀                 |
| `role`       | enum             | 是  | `system` / `user` / `assistant` |
| `content`    | string           | 是  | 消息正文（Markdown 文本）               |
| `tokens`     | int              | 是  | 本条消耗 token，未知填 `0`              |
| `created_at` | string(datetime) | 是  | 消息时间                            |

### 5.3 双端流式输出约定

- 请求：`POST /api/v1/ai/chat`，`stream: true`
- 响应：`text/event-stream`，每帧 `data: {"delta": "文本片段", "conversation_id": "cnv_xxx", "finished": false}`
- 最后一帧：`data: {"delta": "", "conversation_id": "cnv_xxx", "finished": true, "message_id": "msg_xxx"}`
- **双端渲染同一份 Markdown**，小程序端用 `towxml`/自研解析，PC 端用 `markdown-it`，样式分端适配

## 七、补充校验与首版接口约定（v1.2）

### 7.1 字段、身份与权限边界

- 对象字段表描述完整业务对象，不等同于创建或更新请求。请求仅接受接口白名单字段；未知字段返回 HTTP 422、`code=1001`。
- 主键由服务端生成并以唯一约束保证不重复；`created_at`、`updated_at`、`is_deleted`、统计人数、`published_at` 由服务端维护。
- 可选时间及 `publish_date` 未知时返回 `null`；可选文本无值返回 `""`，数组无值返回 `[]`。
- PATCH 中省略字段表示不修改；可空字段显式传 `null` 表示清空。只读字段不能由客户端修改。
- 身份从登录凭证解析，不信任请求中的 `user_id`、`role` 或 `organizer_id`。首版 `organizer_id` 取当前管理人员，`organizer_name` 由服务端读取。
- student 只查看公开活动、操作自己的报名与 AI 会话；librarian/admin 管理活动和报名名单。图书馆业务管理权限不包含任意查看学生私人 AI 会话。
- User 完整对象不得直接作为公共响应；公开页面只返回必要信息。学号、姓名和联系方式不进入公开活动列表；联系方式仅在本人/管理员授权场景返回原值，否则脱敏。
- AI 模型密钥只保存在后端配置；内部 system 消息、完整 Prompt 及调试内容不返回普通客户端。模型、`prompt_version`、`message_count` 和消息 `tokens` 由服务端维护。
- 角色权限和资源归属由后端校验；前端菜单隐藏只用于交互提示。

### 7.2 活动报名规则

1. 活动未删除且 `status=published` 才允许报名。服务器时间须达到 `signup_start_at`，且早于 `signup_end_at` 和 `start_at`；报名开始时间为 null 表示发布后开放，报名截止时间为 null 表示截止于 `start_at`。
2. 发布时校验 `signup_start_at < 实际报名截止时间 <= start_at`；`end_at` 非空时必须晚于 `start_at`。`capacity` 为非负整数，0 表示不限。
3. 首版报名直接为 `approved`；`pending/rejected` 为扩展状态。`signup_count` 统计未删除的 approved 记录，`checkin_count` 统计其中 `checked_in_at` 非空的记录。
4. 余量检查与写入报名在同一事务内完成，避免并发超额。
5. 同一 `activity_id` 与 `user_id` 只保留一条报名关系并建立唯一约束。重复报名返回 HTTP 409、`code=1005`；窗口内取消记录可重新激活并刷新 `signed_up_at`。
6. 签到只允许 ongoing 活动中已批准报名，由后端确认签到凭证；重复签到不增加人数。取消报名接口及规则不属于本轮必做项。
7. 报名接口即使在状态定时处理延迟时，也按实际时间拒绝过期请求。活动开始前先关闭报名，再进入 ongoing。
8. 允许 draft、published、signup_closed 取消；ongoing 可结束为 finished。未定义流转一律拒绝。发布后 capacity 不得低于已报名数。

### 7.3 书目与漂流关系

- Book 表示书目版本，DriftRecord 表示一册漂流实体；`book_id:drift_id` 为一对多。漂流状态、当前持有者、交接地点和流转次数属于 DriftRecord。
- ISBN 用于查找候选书目，不是实体册 ID；无 ISBN 可用 `isbn=""` 手工录入。非空 ISBN 去除空格与连字符，保留末位 X。
- `source=both` 表示书目同时有馆藏和漂流实体；source 由服务端维护。`total_copies`、`available_copies` 仅统计馆藏，且 `0 <= available_copies <= total_copies`。
- `drift_count` 为非负整数；无持有者时 `current_holder_id=null`。摘要来源需可追溯，AI 解读与来源摘要分开。

### 7.4 HTTP 状态与响应体

| HTTP 状态 | code | 用途 |
|---|---:|---|
| 200 / 201 | 0 | 查询/更新成功；创建成功 |
| 422 | 1001 | 字段、时间或枚举校验失败 |
| 401 | 1002 | 缺少或失效登录凭证 |
| 403 | 1003 | 权限不足 |
| 404 | 1004 | 资源不存在、已删除或对请求者不可见 |
| 409 | 1005 | 重复报名、满员、报名截止、非法状态流转 |
| 500 | 5000 | 内部错误；不返回堆栈或密钥 |

所有非流式响应使用 `code/message/data/trace_id`；失败时 `data=null`。分页 `order_by` 必须按接口白名单校验，禁止直接拼接客户端输入。

错误示例：

```json
{"code":1005,"message":"报名已截止","data":null,"trace_id":"d8f1c2a4b6e9"}
```

### 7.5 首版活动接口

需要登录的接口使用 `Authorization: Bearer <token>`。

| 方法与路径 | 权限 | 请求 | 成功 data |
|---|---|---|---|
| GET `/api/v1/activities` | 登录用户 | page/page_size/keyword；order_by 仅 start_at 或 created_at | 分页 ActivityPublic |
| GET `/api/v1/activities/{activity_id}` | 登录用户 | 路径 ID | ActivityPublic；管理人员可获管理详情 |
| POST `/api/v1/activities` | librarian/admin | ActivityCreate | ActivityAdmin，HTTP 201 |
| POST `/api/v1/activities/{activity_id}/publish` | librarian/admin | `{}` | ActivityAdmin |
| POST `/api/v1/activities/{activity_id}/signups` | student | `{}`；身份取凭证 | ActivitySignup，HTTP 201 |
| GET `/api/v1/activities/{activity_id}/signups` | librarian/admin | page/page_size | 分页 ActivitySignupView |

ActivityPublic 白名单：`activity_id`、`title`、`subtitle`、`category`、`cover_url`、`summary`、`content`、`location`、`organizer_name`、`signup_start_at`、`signup_end_at`、`start_at`、`end_at`、`capacity`、`signup_count`、`status`、`need_certificate`。普通用户不可见 draft 和已删除活动。

ActivityAdmin 在公开字段之外增加 `organizer_id`、`checkin_count`、`certificate_template_id`、`ai_copy`、`published_at`、`created_at`、`updated_at`；默认不返回 `is_deleted`。ActivitySignupView 在报名对象字段之外可包含报名者 `name`、`student_no`，仅限上述管理权限。

ActivityCreate 请求示例（`title`/`category`/`start_at` 必填；`capacity` 默认 0，`need_certificate` 默认 false；其他可选文本默认空字符串、时间默认 `null`）：

```json
{
  "title": "校园读书分享会",
  "category": "reading_share",
  "summary": "分享一本喜欢的书",
  "location": "图书馆活动室",
  "signup_start_at": "2026-10-07T09:00:00+08:00",
  "signup_end_at": "2026-10-17T12:00:00+08:00",
  "start_at": "2026-10-18T15:00:00+08:00",
  "end_at": "2026-10-18T17:00:00+08:00",
  "capacity": 30,
  "need_certificate": false
}
```

ActivityCreate 其余可选白名单为 `subtitle`、`cover_url`、`content`、`certificate_template_id`；需要证书时发布前校验证书模板存在。服务端创建为 draft，人数为 0，`published_at=null`；发布时改为 published 并填入发布时间。返回完整 ActivityAdmin，而非仅返回 ID。

报名成功示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "signup_id": "sgn_9f2a1c77b0d4",
    "activity_id": "act_9f2a1c77b0d4",
    "user_id": "usr_9f2a1c77b0d4",
    "status": "approved",
    "signed_up_at": "2026-10-08T10:00:00+08:00",
    "checked_in_at": null,
    "certificate_no": "",
    "created_at": "2026-10-08T10:00:00+08:00",
```

统一失败：参数错误 1001、未登录 1002、无权限 1003、不可见/不存在 1004；发布状态非法、重复报名、满员或截止返回 1005。列表查询成功但无数据时 `list=[]`、`total=0`。

### 7.6 AI 及资源地址补充

- `/api/v1/ai/chat` 为既有流式协议路径例外，不由双端自行改名；本轮 `stream=false` 返回统一响应体，`data` 包含 `conversation_id`、`message_id`、`content`。
- 请求白名单：`conversation_id`（首次为 null）、`book_id`（可为 null）、`scene`、`content`、`stream`。服务端校验既有会话归属；用户不得提交 system 消息、他人 `user_id`、模型或 Prompt 元数据。
- SSE 每个事件以两个换行结束；开始传输前的错误使用 7.4 普通 JSON 响应。流内失败发送 `data` 对象，包含 `code`、`message`、`conversation_id`、`finished=true`、`error=true`，随后关闭连接。
- 未收到 `finished=true` 即断连视为回答未完成，前端提示重试，不自动把半截回答标为成功。流式实现不属于本轮字段文档验收的必做项。
- 非空 `cover_url` 统一为站内以 `/` 开头的资源路径，如 `/assets/books/example.jpg`；为空时使用默认封面。外部封面须经后端接入为统一资源路径；双端使用相同资源 baseURL。
- 摘要来源需可追溯；来源摘要 `summary` 与模型生成的 `ai_summary` 分开保存。
- 本文为字段及接口草案；成员确认与代码联调应另留记录，不以文档存在替代运行验收。
