# 「智阅校园」核心数据对象与统一字段规范（v1.3）

> 适用范围：第 1 轮开发周期（2026-10-06 ~ 2026-10-18）  
> 目标：**统一字段口径，按变更记录维护，避免双端（PC 端 Vue / 微信小程序）联调时数据不一致**  
> 维护人：万贝　｜ 需要变更时：在本文件登记「变更记录」后同步后端 Schema 与前端字段常量

## 一、全局约定（必须先看这一节）

### 1.1 命名规则

| 项目       | 约定                 | 说明                                              |
| -------- | ------------------ | ----------------------------------------------- |
| JSON 字段名 | `snake_case`       | 前后端保持一致，不做自动驼峰转换，减少联调歧义                         |
| 对象名      | 大驼峰                | `User` / `Activity` / `Book` / `AIConversation` |
| 枚举值      | 小写 `snake_case` 英文 | 如 `signup_closed`，中文只用于展示映射                     |
| URL 路径   | 复数、小写、中划线          | `/api/v1/activities`、`/api/v1/ai/conversations` |

### 1.2 主键规则（重要）

**所有主键统一为字符串（string），格式 `前缀 + 12 位十六进制`**，例如 `usr_9f2a1c77b0d4`。

- 前缀：`usr_` 用户、`act_` 活动、`bok_` 图书、`cnv_` 会话、`drf_` 漂流记录、`sgn_` 报名记录、`rpt_` 活动报道、`msg_` 消息
- **不使用自增 int64 作为对外主键**：JS `Number` 精度有限，用字符串可避免小程序/PC 端 ID 被截断

### 1.3 时间与时区

- 统一使用 **ISO 8601 带时区偏移字符串**，时区 `+08:00`，例：`"2026-10-18T12:00:00+08:00"`
- 字段名统一 `_at` 结尾表示「时间点」，`_date` 结尾表示「日期」
- 后端存储用 UTC，序列化时统一转换为 `+08:00`

### 1.4 通用基础字段（BaseModel，所有业务对象统一继承）

`User`、`Activity`、`Book`、`AIConversation` 以及后续新增的 `ActivitySignup`、`ActivityReport`、`DriftRecord` 等业务对象，统一继承 `BaseModel`。除各对象自身业务字段外，默认都包含以下通用字段；后续对象表格中即使只简写 `created_at / updated_at`，也视为同时包含 `is_deleted`。

| 字段           | 类型               | 必填 | 说明                                 |
| ------------ | ---------------- | -- | ---------------------------------- |
| `created_at` | string(datetime) | 是  | 创建时间，服务端生成，客户端只读                   |
| `updated_at` | string(datetime) | 是  | 最后更新时间，服务端生成，客户端只读                 |
| `is_deleted` | boolean          | 是  | 软删除标记，默认 `false`；列表接口默认只返回 `false` |

### 1.5 空值规范

- 普通可选文本无值用 `""`；必填文本不得为空。可选日期、时间点及不存在的关联 ID 使用 `null`，禁止用空字符串代替日期或时间。
- 数值：计数类统一用 `0` 而非 `null`
- 数组：无值用 `[]`，禁止 `null`
- 布尔：禁止用 `0/1` 代替 `true/false`

### 1.6 统一响应体

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "trace_id": "d8f1c2a4b6e9"
}
```

| code | 含义                  |
| ---- | ------------------- |
| 0    | 成功                  |
| 1001 | 参数校验失败              |
| 1002 | 未登录 / token 失效      |
| 1003 | 无权限（RBAC 拦截）        |
| 1004 | 资源不存在               |
| 1005 | 业务状态非法（如未发布的活动不能签到） |
| 5000 | 服务器内部错误             |

### 1.7 统一分页

请求参数：`page`（从 1 开始，默认 1）、`page_size`（默认 20，最大 100）、`keyword`（模糊搜索）、`order_by`、`order`（`asc`/`desc`）

响应 `data`：

```json
{
  "list": [],
  "page": 1,
  "page_size": 20,
  "total": 128
}
```

| `class_no`                  | string           | 否  | 班级，如「2025217802」                  |
| `grade`                     | string           | 否  | 年级，如「2025」                        |

### 2.1 角色枚举 `role`

| 值           | 含义         | 权限范围                   |
| ----------- | ---------- | ---------------------- |
| `student`   | 学生（小程序端主体） | 浏览活动、报名签到、AI 伴读、图书漂流   |

### 2.2 隐私约定

- `phone`、`email` 在**非本人、非管理员**请求下返回脱敏值：`177****3115`、`21****@qq.com`
- 加密存储字段（后续接 AES-GCM）：`phone`、`email`

### 3.2 状态机 `status`（管理端与小程序端必须共用）

```
draft(草稿) ──publish──▶ published(已发布) ──close_signup──▶ signup_closed(报名截止)
                                   │                                  │
                                   └────────cancel───▶ cancelled      └──start──▶ ongoing(进行中)
                                                                                     │
                                                                                  finish
                                                                                     ▼
                                                                            finished(已结束)
```

| 值               | 展示文案 | 是否可编辑 | 是否可报名 |
| --------------- | ---- | ----- | ----- |
| `draft`         | 草稿   | 是     | 否     |
| `published`     | 已发布  | 是     | 按7.2判断 |
| `signup_closed` | 报名截止 | 是     | 否     |
| `ongoing`       | 进行中  | 是     | 否     |
| `finished`      | 已结束  | 否     | 否     |
| `cancelled`     | 已取消  | 否     | 否     |

> **非法流转必须由后端拦截并返回 `code=1005`**，前端只做按钮可用性提示，不做唯一判断。

### 3.3 派生对象（本轮定义字段，实现周期另行确认）

> **命名约定：**活动报名/参与关系统一使用 `ActivitySignup`。任务清单中的 `ActivityParticipant` 是历史名称，与 `ActivitySignup` 指向同一业务对象；新文档、FastAPI Schema、数据库表及前端类型均使用 `ActivitySignup`。

| `ActivityReport` | `report_id` / `activity_id` / `title` / `content` / `images[]` / `published_at`                          | 活动报道与成果展示                                                    |

#### 3.3.1 ActivitySignup 完整字段

“必填”表示持久化对象中必须有该字段；客户端是否可写以“写入规则”为准。创建报名接口不接受客户端提交对象字段，报名人由登录凭证确定。

| `status` | enum | 是 | `approved` | 首版报名时由服务端设为 `approved`；状态变更只能走业务操作 |

| `checked_in_at` | string(datetime) 或 null | 是 | `null` | 签到操作由服务端更新，客户端只读 |
| `certificate_no` | string | 是 | `""` | 证书生成后由服务端写入，客户端只读 |
| `created_at` | string(datetime) | 是 | 服务端当前时间 | 通用字段，服务端只读 |
| `updated_at` | string(datetime) | 是 | 服务端当前时间 | 通用字段，服务端只读 |

`status` 枚举为 `pending` / `approved` / `rejected` / `cancelled`。首版新报名直接为 `approved`；`pending`、`rejected` 为预留扩展状态。取消和重新报名规则按 7.2 执行。`checked_in_at` 未签到时为 `null`，`certificate_no` 未生成时为空字符串。

### 4.1 图书漂流字段概览（`source = drift` 或 `both` 时适用）

下表仅用于说明 `Book` 与漂流业务的关联概念；正式存储对象的字段类型、必填性、默认值及写入规则以本节后的 `DriftRecord` 完整字段表为准。

| 字段                  | 类型     | 说明                                                                                |
| ------------------- | ------ | --------------------------------------------------------------------------------- |
| `book_id`           | string | 关联Book主键；同一book_id允许关联多个drift_id |
| `drift_id`          | string | 漂流记录 ID，`drf_` 前缀                                                                 |
| `drift_status`      | enum   | `idle`(待领取) / `reserved`(已预定) / `in_transit`(流转中) / `claimed`(已领用) / `closed`(下架) |
| `current_holder_id` | string 或 null | 当前持有者 `user_id`；无持有人时为 `null`                                                                   |
| `drift_location`    | string | 线下交接地点，如「图书馆一层大厅」                                                                 |
| `drift_count`       | int    | 累计流转次数                                                                            |

> **第 1 轮实现约定：**上述漂流扩展字段可暂时作为 `Book` 的开发占位字段，用于页面原型、接口 Mock 与最小链路联调，不要求本轮完成独立漂流表。
>
> **命名约定：**任务清单中的 `BookFlow` 是历史名称，与 `DriftRecord` 指向同一漂流实体记录；新文档、Schema、数据库表和前端类型统一使用 `DriftRecord` / `drift_records`。正式实现时，`Book` 仅保留图书主数据；漂流状态、持有者、交接地点和流转次数迁移至 `DriftRecord`。本轮占位数据不得覆盖一个书目关联多册漂流实体的关系。

#### DriftRecord 完整字段

| 字段 | 类型 | 必填 | 默认值/空值 | 写入规则 |
|---|---|---:|---|---|
| `drift_id` | string | 是 | 服务端生成，`drf_` 前缀 | 服务端生成，客户端只读 |
| `book_id` | string | 是 | 无 | 必须关联现有 `Book`；不得由普通用户改绑 |
| `drift_status` | enum | 是 | `idle` | 初始值 `idle`；仅允许通过服务端业务操作流转 |
| `current_holder_id` | string 或 null | 是 | `null` | 持有人身份由服务端从凭证解析；客户端不得直接指定或改写 |
| `drift_location` | string | 是 | `""` | 无地点为空字符串；通过有权限的交接/管理操作更新 |
| `drift_count` | int | 是 | `0` | 非负；由服务端在完成一次有效流转时维护，客户端只读 |
| `created_at` | string(datetime) | 是 | 服务端当前时间 | 通用字段，服务端只读 |
| `updated_at` | string(datetime) | 是 | 服务端当前时间 | 通用字段，服务端只读 |
| `is_deleted` | boolean | 是 | `false` | 通用字段，服务端只读 |

`drift_status` 枚举为 `idle` / `reserved` / `in_transit` / `claimed` / `closed`。无持有人时 `current_holder_id=null`。当前首版接口的流转为：上架创建 `idle` 记录，并从登录凭证设置持有人；申领仅允许 `idle` / `reserved` 转为 `claimed`，服务端将持有人更新为当前用户，并在条件更新成功时将 `drift_count` 原子递增一次；并发重复申领失败并返回 HTTP 409 / `code=1005`。下架将非 `closed` 记录改为 `closed`，不递增流转次数。当前没有将记录转为 `reserved` 或 `in_transit` 的业务接口，这两个枚举值暂不代表已实现完整流程。

| `user_id`                   | string           | 是  | 会话归属用户                                  |
| `scene`                     | enum             | 是  | 见 5.1 场景枚举                              |
| `title`                     | string           | 否  | 会话标题，默认取首条用户提问前 20 字                    |
| `book_id`                   | string或null     | 否  | 关联图书；通用问答为 `null`                       |
| `book_title`                | string           | 否  | 冗余书名，便于列表展示                             |
| `model`                     | string           | 是  | 使用的模型标识，如 `deepseek-chat` / `qwen-plus` |
| `messages`                  | Message[]        | 是  | 消息数组，默认 `[]`，见 5.2                      |
| `message_count`             | int              | 是  | 消息条数                                    |
| `prompt_version`            | string           | 是  | 提示词版本号，如 `v1.0-book-analysis`，便于效果回溯    |
| `status`                    | enum             | 是  | `active` / `archived`，默认 `active`       |
| `created_at` / `updated_at` | string(datetime) | 是  | 通用字段                                    |

### 5.1 场景枚举 `scene`

| 值               | 含义        | 对应端           |
| --------------- | --------- | ------------- |
| `book_analysis` | 书目深度解读    | PC 端 + 小程序端   |
| `recommend`     | 智能推荐及推荐理由 | PC 端          |
| `qa`            | 多轮伴读问答    | 小程序端为主，PC 端可用 |
| `copywriting`   | 推文/宣传文案生成 | PC 端管理后台      |

### 5.2 消息对象 Message

| 字段           | 类型               | 必填 | 说明                              |
| ------------ | ---------------- | -- | ------------------------------- |
| `message_id` | string           | 是  | 消息 ID，`msg_` 前缀                 |
| `role`       | enum             | 是  | `system` / `user` / `assistant` |
| `content`    | string           | 是  | 消息正文（Markdown 文本）               |
| `tokens`     | int              | 是  | 本条消耗 token，未知填 `0`              |
| `created_at` | string(datetime) | 是  | 消息时间                            |

### 5.3 双端流式输出约定

- 请求：`POST /api/v1/ai/chat`，`stream: true`
- 响应：`text/event-stream`，每帧 `data: {"delta": "文本片段", "conversation_id": "cnv_xxx", "finished": false}`
- 最后一帧：`data: {"delta": "", "conversation_id": "cnv_xxx", "finished": true, "message_id": "msg_xxx"}`
- **双端渲染同一份 Markdown**，小程序端用 `towxml`/自研解析，PC 端用 `markdown-it`，样式分端适配

## 七、补充校验与首版接口约定（v1.3）

### 7.1 字段、身份与权限边界

- 对象字段表描述完整业务对象，不等同于创建或更新请求。请求仅接受接口白名单字段；未知字段返回HTTP 422、code=1001。
- 主键由服务端生成并以唯一约束保证不重复；生成碰撞时重试。created_at、updated_at、is_deleted、统计人数、published_at由服务端维护。
- 可选时间包括last_login_at、signup_start_at、signup_end_at、end_at、published_at、checked_in_at、ai_summary_updated_at；未发生或未知时返回null。publish_date未知时也返回null。
- PATCH中省略字段表示不修改；可空字段显式传null表示清空。只读字段不能由客户端修改。
- 身份从登录凭证解析，不信任请求中的user_id、role或organizer_id。首版organizer_id取当前管理人员，organizer_name由服务端读取；后续委托创建需单独定义权限。
- student只查看公开活动、操作自己的报名与AI会话；librarian/admin管理活动和报名名单。图书馆业务管理权限不包含任意查看学生私人AI会话。
- User完整对象不得直接作为公共响应；公开页面仅返回必要信息。学号、姓名、联系方式不进入公开活动列表；联系方式仅在授权接口返回本人/管理员原值或业务所需脱敏值。
- AI模型密钥只保存在后端配置，不提交到代码仓库或前端。内部system消息、完整Prompt及内部调试内容不返回普通客户端。
- 模型、prompt_version、message_count与消息tokens由服务端维护；message_count统计对用户可见的user/assistant消息，tokens未知为0。
- 角色权限校验及资源归属校验均由后端执行；前端菜单隐藏仅用于交互提示。
- **待图书馆/指导教师确认的身份假设：**本草案暂以学号/工号作为 `student_no` 和登录账号字段；尚未确认是否接入学校统一身份认证、账号数据由谁提供及账号状态如何同步。`librarian` / `admin` 角色应由授权管理流程赋予，普通客户端不得自行提交或修改角色；具体授权人、审批流程和管理员初始化方式待确认。
- **待确认的数据来源与权限：**前期仅使用脱敏馆藏数据或模拟借阅榜单。馆藏数据可导出字段、数据更新频率、保存期限、使用授权，以及 BALIS 接口是否可用、调用凭证由谁保管、允许调用的字段和用途，均须由图书馆/指导教师确认后再接入真实数据。确认前不得把接口可用或已获数据授权写成既成事实。
- **安全实现状态：**手机号、邮箱的加密存储（计划采用 AES-GCM）属于后续实现事项，当前版本尚未落地，不作为已实现功能描述。接入真实个人信息前，需完成密钥管理、加解密、脱敏响应及权限验证的实现和验证。

### 7.2 活动报名规则

以下规则作为3.2“是否可报名”的共同判断依据：

1. 活动未删除且status=published；服务器时间达到signup_start_at，且严格早于signup_end_at及start_at。signup_start_at为null表示发布后开放；signup_end_at为null表示截止于start_at。
2. 发布时校验signup_start_at < 实际报名截止时间 <= start_at；end_at非空时必须大于start_at。capacity必须为非负整数。
3. 首版不启用人工审核，报名直接为approved；pending/rejected保留为扩展状态。signup_count只统计未删除的approved记录，checkin_count统计这些记录中checked_in_at非空的数量。
4. capacity=0表示不限；否则signup_count必须小于capacity。检查余量与写入报名在同一事务内完成，避免并发超额。
5. 同一activity_id与user_id只保留一条报名关系并建立唯一约束；已有approved/pending报名时返回HTTP 409、code=1005，不重复计数。cancelled记录在报名窗口内可重新激活为approved，刷新signed_up_at。
6. 签到仅允许ongoing活动中已批准的报名，由后端确认签到凭证；重复签到不增加人数。取消报名不作为本轮必做接口，正式实现前补齐其时间限制及计数更新规则。
7. published到signup_closed在报名截止后由服务端处理；即使定时任务延迟，报名接口仍按实际时间拒绝请求。开始活动前可先执行关闭报名，再进入ongoing。
8. 允许draft、published、signup_closed取消为cancelled；ongoing结束为finished。其他未定义流转拒绝。发布后不得把capacity降到已报名人数以下；涉及报名时间或地点修改需明确通知已报名用户。

### 7.3 书目与漂流关系

- Book表示书目版本，DriftRecord表示一册漂流实体的当前业务记录；book_id:drift_id为一对多。
- ISBN用于查找候选书目，不作为实体册ID；无ISBN的图书允许isbn=""并手动录入。非空ISBN去除空格和连字符，保留可能的末位X。
- source=both表示同一书目同时有馆藏和漂流实体；source由服务端依据数据来源维护。total_copies、available_copies仅统计馆藏，不包含漂流册；0 <= available_copies <= total_copies。
- 同一书目多册时使用多个DriftRecord记录，不在Book中保存单一drift_id；漂流状态与持有人只由服务端业务接口维护。
- DriftRecord至少包含drift_id、book_id、drift_status、current_holder_id、drift_location、drift_count及通用字段。drift_count为非负整数，current_holder_id无持有者时为null。
- 书目摘要需记录可追溯来源；模型生成的ai_summary与来源摘要summary分开保存。
- 馆藏、借阅榜单及 BALIS 数据来源与授权状态按 7.1 标记为待确认；确认前开发和演示使用脱敏或模拟数据，并在数据样例中标注来源类型。
- `DriftRecord` 完整存储字段见 4.1；扩展字段占位不得被解释为加密存储或真实漂流流程已经完成。

### 7.4 HTTP状态与响应体

| HTTP状态 | code | 用途 |
|---|---|---|
| 200 / 201 | 0 | 查询/更新成功；创建成功 |
| 422 | 1001 | 字段、时间或枚举校验失败 |
| 401 | 1002 | 缺少或失效登录凭证 |
| 403 | 1003 | 权限不足 |
| 404 | 1004 | 资源不存在、已删除或对请求者不可见 |
| 409 | 1005 | 重复报名、满员、报名截止、非法状态流转 |
| 500 | 5000 | 内部错误；不返回堆栈或密钥 |

所有非流式响应均使用code/message/data/trace_id结构；失败时data=null。分页order_by按接口白名单校验，禁止直接拼接客户端输入。

错误示例：
```json
{"code":1005,"message":"报名已截止","data":null,"trace_id":"d8f1c2a4b6e9"}
```

### 7.5 首版活动接口

需要登录的接口使用Authorization: Bearer <token>。以下为开发约定，不代表接口已实现。

| 方法与路径 | 权限 | 请求 | 成功data |
|---|---|---|---|
| GET /api/v1/activities | 登录用户 | page/page_size/keyword；order_by仅允许start_at或created_at | {list:[ActivityPublic],page,page_size,total} |
| GET /api/v1/activities/{activity_id} | 登录用户 | 路径ID | ActivityPublic；管理人员可获取管理详情 |
| POST /api/v1/activities | librarian/admin | ActivityCreate | ActivityAdmin，HTTP 201 |
| POST /api/v1/activities/{activity_id}/publish | librarian/admin | {} | ActivityAdmin，HTTP 200 |
| POST /api/v1/activities/{activity_id}/signups | student | {}；用户身份取凭证 | ActivitySignup，HTTP 201 |
| GET /api/v1/activities/{activity_id}/signups | librarian/admin | page/page_size | {list:[ActivitySignupView],page,page_size,total} |

ActivityPublic白名单：activity_id、title、subtitle、category、cover_url、summary、content、location、organizer_name、signup_start_at、signup_end_at、start_at、end_at、capacity、signup_count、status、need_certificate。普通用户不可见draft和已删除活动。

ActivityAdmin在公开字段之外增加organizer_id、checkin_count、certificate_template_id、ai_copy、published_at、created_at、updated_at；默认不返回is_deleted。ActivitySignupView在报名对象字段之外可包含报名者name、student_no，仅限上述管理权限。

ActivityCreate请求示例（title/category/start_at必填；capacity默认0，need_certificate默认false；其他可选文本默认空字符串、时间默认null）：
```json
{
  "title":"校园读书分享会",
  "category":"reading_share",
  "summary":"分享一本喜欢的书",
  "location":"图书馆活动室",
  "signup_start_at":"2026-10-07T09:00:00+08:00",
  "signup_end_at":"2026-10-17T12:00:00+08:00",
  "start_at":"2026-10-18T15:00:00+08:00",
  "end_at":"2026-10-18T17:00:00+08:00",
  "capacity":30,
  "need_certificate":false
}
```

ActivityCreate其余可选白名单为subtitle、cover_url、content、certificate_template_id；需要证书时发布前校验证书模板存在。服务端创建为draft，人数为0，published_at=null；发布时改为published并填入发布时间。返回完整ActivityAdmin，而非仅返回ID。

报名成功示例：
```json
{
  "code":0,
  "message":"ok",
  "data":{
    "signup_id":"sgn_9f2a1c77b0d4",
    "activity_id":"act_9f2a1c77b0d4",
    "user_id":"usr_9f2a1c77b0d4",
    "status":"approved",
    "signed_up_at":"2026-10-08T10:00:00+08:00",
    "checked_in_at":null,
    "certificate_no":"",
    "created_at":"2026-10-08T10:00:00+08:00",
    "updated_at":"2026-10-08T10:00:00+08:00"
  },
  "trace_id":"d8f1c2a4b6e9"
}
```

该响应示例与 3.3.1 的 `ActivitySignup` 业务字段一致：`signup_id`、`user_id`、状态和时间由服务端生成；未签到的 `checked_in_at` 为 `null`，未生成证书时 `certificate_no` 为 `""`。报名请求体为 `{}`，未知或额外字段按 7.1 白名单规则拒绝。签到字段只能由后端签到业务操作更新，不能通过报名创建或普通 PATCH 写入。`ActivitySignup` 持久化对象包含 `is_deleted`；面向报名者的成功响应可省略该内部软删除字段，服务端仍须维护它。

漂流写接口为 `POST /api/v1/drift/books`（上架）及 `POST /api/v1/drift/records/{drift_id}/claim`（申领）；管理接口 `POST /api/v1/drift/records/{drift_id}/close` 用于下架。请求不接受客户端指定的 `current_holder_id` 或 `drift_count`；申领状态、持有人及次数按 4.1 由服务端维护。当前没有预定或流转中状态的写入接口。

### 7.6 AI及资源地址补充

- /api/v1/ai/chat为已有流式协议路径例外，不由双端自行改名。本轮允许stream=false：返回统一响应体，data包含conversation_id、message_id、content。
- 请求白名单：conversation_id（首次为null）、book_id（可为null）、scene、content、stream；服务端校验既有会话归属，用户不可提交system消息或指定他人user_id。
- SSE每个事件以两个换行结束；开始传输前的错误使用7.4普通JSON响应。流内失败发送data对象，包含code、message、conversation_id、finished=true、error=true；随后关闭连接。
- 未收到finished=true即断连视为回答未完成，前端提示重试，不自动将半截回答标为成功。流式实现不属于本轮字段文档验收的必做项。
- cover_url非空时统一为站内以/开头的资源路径，如/assets/books/example.jpg；为空时使用默认封面。外部封面须经后端接入为统一资源路径；双端使用相同资源baseURL。
- 本文为字段及接口草案；成员确认与代码联调应另留记录，不以文档存在替代运行验收。
