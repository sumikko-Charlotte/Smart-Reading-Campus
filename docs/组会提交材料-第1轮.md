## 三、需要组会确认的 5 个问题

1. **活动分类枚举是否够用？** 现为 6 类（`reading_share`/`lecture`/`exhibition`/`reading_challenge`/`book_drift`/`other`）。若图书馆还有「志愿服务」「信息素养培训」等类型，需扩枚举——前后端各改一处（`core/enums.py` 与 `web-pc/src/constants/index.js`），越早定越省事。
2. **`source=both` 由谁判定？** 是馆藏系统导入时自动置 `both`，还是管理端录入时手工选择？这决定图书录入页要不要做「馆藏 / 漂流 / 两者均有」选择项。
3. **证书模板由谁负责？** 本轮发布校验只校验 `certificate_template_id` 非空。是否需要把 `certificate_template` 作为对象补进规范、由谁维护模板内容。
4. **`cover_url` 站内路径约定。** 建议统一为 `/assets/...` 并抽成前后端共用配置项；小程序端资源域名是否与 PC 端走同一网关，需要确认（涉及小程序 downloadFile 域名白名单）。
5. **报名是否永久不做人工审核？** v1.2 写「首版不启用、报名直接 `approved`」。若确认，管理端就不做审核按钮，`pending`/`rejected` 仅作为数据层扩展状态保留。

4. 在草稿上点「发布」→ 状态变 `published` 且写入 `published_at`。

6. 学生报名 → 返回 `status=approved`；再报一次 → 409 / `code=1005`（重复报名）。
